# PRO Инсульт — приложение (v2)

Expo SDK 58 · React Native · Expo Router · Supabase. Дизайн — по макету `../проект/PRO_Инсульт_новый_дизайн*.html`.

## Что сделано

- Вход и регистрация по номеру телефона: код из СМС (6 цифр, не чаще раза в минуту, действует 5 минут).
  Новый номер → выбор роли (пациент / ухаживающий / врач) → имя и согласие (152-ФЗ) → личный номер.
- Личный номер выдаёт сервер: `#пац-0001`, `#ухаж-0001`, `#врач-0001` (свой счётчик у каждой роли).
- Кнопка «Войти через VK ID» — неактивна до регистрации приложения в VK ID.
- Личный кабинет: номер с копированием, связь по номеру (пациент ↔ врач, ухаживающий ↔ пациент)
  с подтверждением второй стороной, выход.
- Разделы из макета с нижним меню: **Главный** (кольцо выполнения, «Начать занятие», графики прогресса и
  занятий за неделю), **Занятия** (блоки мышление / моторика / речь), **Чат и показатели**, **Покупки**.
  **Упражнения «Речь»** (вкладка «Занятия» → «РЕЧЬ · все упражнения»): губы трубочкой, уголки губ, язык вперёд,
  перекат воздуха. Сверху видео-пример (`assets/exercises/speech`), снизу фронтальная камера в тонкой рамке:
  серая — ждём движения, зелёная — верно, жёлтая — не до конца или неравномерно; считаются повторы.
  Проверка — MediaPipe Face Landmarker (коэффициенты мимики) прямо в браузере, видео никуда не отправляется;
  пороги в `src/lib/exercises.ts`. В приложении на телефоне камера есть, автопроверки пока нет; язык не проверяется.
  По нажатию на график «Занятия» открывается календарь по месяцам (что сделано в каждый день, итоги месяца).
  Профиль с личным номером и связями — по нажатию на аватар. У врача на главном — список его пациентов.
  Данные занятий, оценок и чата пока демонстрационные (`src/lib/demo.ts`), ассистент «Брэйни» — заглушка.
- **Вход для разработчика** без СМС: на стартовом экране и в профиле кнопки «Пациент / Ухаживающий / Врач»
  (тестовые номера +7 999 000-00-01 / 02 / 03). Виден только в режиме разработки
  или при `EXPO_PUBLIC_DEV_LOGIN=1` в `.env`.
- Светлая и тёмная тема (переключатель на каждом экране входа и в кабинете).
- Согласие на обработку персональных данных при регистрации (152-ФЗ), время согласия сохраняется.

## Запуск

```bash
npm install
npx expo start          # QR-код → Expo Go
npx expo start --web    # в браузере
```

Ключи Supabase — в `.env` (образец `.env.example`).

## Сервер

- Проект Supabase — **pro-insult-app** (`exjpswhcriymikhsnvdz`). Старый проект prototipe не используется.
  Бесплатный проект засыпает после 7 дней без активности — включается в панели кнопкой Restore.
- Схема базы: `supabase/schema.sql` (выполняется целиком, повторно — тоже можно).
- Вход по телефону включён. Тестовые номера без СМС: +7 999 000-00-01 … 04, коды 111111 … 444444.
- Отправка настоящих СМС: функция `public.send_sms_hook` в базе (`supabase/sms-hook.sql`) отправляет код
  через SMS.ru. Ключ SMS.ru хранится в Vault базы под именем `smsru_api_id` (кладётся вручную, см. файл).
- **Не работает:** SMS.ru отклоняет отправку (ошибка 221) — нужен зарегистрированный буквенный отправитель,
  а физическим лицам SMS.ru его не регистрирует. Нужен другой способ доставки кода (решение отложено).
  Ответы SMS.ru видны в таблице `net._http_response`.

## Где хранятся данные

Сейчас — облачный Supabase (бесплатный тариф, сервер за рубежом): только разработка и тестовые данные.
Для реальных пациентов (152-ФЗ) — переезд на свой сервер в России: `infra/server/setup.sh` ставит
Supabase на чистую Ubuntu 24.04 одной командой (Docker, HTTPS через Caddy, вход по телефону, СМС-хук,
ежедневные резервные копии). Код приложения при переезде не меняется — только адрес и ключ в `.env`.

```
                  calendar; speech/ — список упражнений и экран упражнения

src/lib/          supabase, Auth (вход и регистрация), links, people (связи), dev, demo, exercises, validation
src/theme/        цвета и шрифты из макета
supabase/         schema.sql, sms-hook.sql
infra/server/     установка собственного сервера (на будущее)
```
