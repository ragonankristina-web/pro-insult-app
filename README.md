# PRO Инсульт — приложение (v2)

Expo SDK 58 · React Native · Expo Router · Supabase. Дизайн — по макету `../проект/PRO_Инсульт_новый_дизайн*.html`.

## Что сделано

- Вход и регистрация по номеру телефона: код из СМС (6 цифр, не чаще раза в минуту, действует 5 минут).
  Новый номер → выбор роли (пациент / ухаживающий / врач) → имя и согласие (152-ФЗ) → личный номер.
- Личный номер выдаёт сервер: `#пац-0001`, `#ухаж-0001`, `#врач-0001` (свой счётчик у каждой роли).
- Кнопка «Войти через VK ID» — неактивна до регистрации приложения в VK ID.
- Личный кабинет: номер с копированием, связь по номеру (пациент ↔ врач, ухаживающий ↔ пациент)
  с подтверждением второй стороной, выход.
- Разделы из макета с нижним меню: **Главный** (кольцо выполнения, «Начать занятие», графики прогресса и
  занятий за неделю), **Занятия** (блоки мышление / моторика / речь), **Чат и показатели**, **Покупки**.
  **Упражнения «Речь»** (вкладка «Занятия» → «РЕЧЬ · все упражнения»): губы трубочкой, уголки губ, язык вперёд,
  перекат воздуха. Сверху видео-пример (`assets/exercises/speech`), снизу фронтальная камера в тонкой рамке:
  серая — ждём движения, зелёная — верно, жёлтая — не до конца или неравномерно; считаются повторы.
  Проверка — MediaPipe Face Landmarker (коэффициенты мимики) прямо в браузере, видео никуда не отправляется;
  пороги в `src/lib/exercises.ts`. В приложении на телефоне камера есть, автопроверки пока нет; язык не проверяется.
  **Мышление → «Фруктовый сад»** (вкладка «Занятия» → «МЫШЛЕНИЕ · все упражнения»): 6 уровней сортировки фруктов
  по корзинам, спокойный режим и режим на время, пауза, итоги уровня. Корзину выбирают нажатием (в браузере ещё
  клавишами 1–4 и ← →), голосом — номер корзины или «левая/правая» (Web Speech API, Chrome/Edge; в Chrome речь
  распознаётся на серверах Google) и поднятой рукой перед камерой (RTMPose, на устройстве): левая — корзина 1,
  правая — последняя. Голос и руки пока только в браузере. Логика — `src/lib/fruitGame.ts`.
  По нажатию на график «Занятия» открывается календарь по месяцам (что сделано в каждый день, итоги месяца).
  Профиль с личным номером и связями — по нажатию на аватар. У врача на главном — список его пациентов.
  Данные занятий, оценок и чата пока демонстрационные (`src/lib/demo.ts`).
- **Чат пациент ↔ врач — настоящий**: таблица `messages` в Supabase (`supabase/chat.sql`), писать можно только
  тому, с кем связь подтверждена; новые сообщения и «✓✓ прочитано» приходят сразу (Realtime). Пока связи нет,
  в чате показан пример переписки. Код — `src/lib/chat.tsx`.
  **Видеокружки**, как в Telegram: переключатель 🎙 / ⭕ у поля ввода, запись до минуты (MediaRecorder в браузере),
  просмотр, переснять или отправить. Видео — в закрытом хранилище Supabase `video-notes` (`supabase/video-notes.sql`),
  смотреть могут только двое из переписки. Записывать — пока в браузере, смотреть — и в приложении на телефоне.
- **Кабинет врача** (по макету «врач вкладки»): 5 вкладок — «Занятия», «Чаты», «Врач» (главная, большая кнопка
  посередине), «Статистика», «Покупки». «Врач» — календарь всех занятий на месяц и карточки «Сегодня» / «Завтра».
  «Чаты» — все пациенты списком, как в мессенджере, и переписка с каждым. «Занятия» — групповые и индивидуальные
  занятия, назначение нового (`/session/new`) и «Библиотека упражнений» (`/library`). «Статистика» — мои пациенты
  плиткой, по нажатию — показатели пациента (`/patient/[id]`). «Покупки» — кошелёк, операции, функции для работы.
  Пациенты — по подтверждённым связям, пока их нет — пример; расписание и кошелёк — демо (`src/lib/clinic.tsx`).
- **Захват движений — RTMPose** (OpenMMLab, Apache-2.0): модель RTMPose-m whole-body, 133 точки — тело, стопы,
  лицо, кисти с пальцами. Работает в браузере через ONNX Runtime Web на видеокарте (WebGPU), иначе на процессоре;
  кадры не покидают устройство. Модель (~70 МБ) — `public/models`, математика — `src/lib/rtmpose.ts`,
  камера со скелетом — `src/components/PoseCamera.web.tsx`. **Моторика → «Захват движений»**: углы подъёма рук и
  локтей, раскрытие кистей (%), максимумы и разница левой и правой стороны. На телефоне — после отдельной сборки.
- **Ассистент «Брэйни»** — сам персонаж поверх всех экранов кабинета (утверждённые анимации `assets/brainy`:
  спокойная поза, разговор, счастье, грусть, злость; `src/components/BrainyAvatar.tsx`, настроение — `src/lib/brainyMood.ts`).
  Эмоции — на слова пациента, свои ответы и упражнения (повтор в «Речи», выбор в игре, высоко поднятая рука). Отзывается на имя («Брэйни, открой речь»;
  включается галочкой в его окне), открывает разделы и упражнения, объясняет технику по карточкам упражнений
  (не придумывает), отвечает, что на сегодня, ставит напоминания («напомни в 18:00», «через 30 минут» — пока
  срабатывают, только когда приложение открыто) и пишет в чат с врачом под диктовку — с подтверждением
  «отправить / заново / отмена». На слова о признаках инсульта показывает кнопки «Позвонить 103 / 112».
  Без платного ИИ: словарь команд в `src/lib/brainy.ts`. Голос в браузере — «Руслан» (Piper, на устройстве,
  `src/lib/piperWeb.ts`; лицензия голоса некоммерческая — см. `public/models/README.md`), на телефоне — голос устройства,
  распознавание — то же, что в игре (одно общее на приложение). Голосом — в браузере; на телефоне пока текстом.
- **Вход для разработчика** без СМС: на стартовом экране и в профиле кнопки «Пациент / Ухаживающий / Врач»
  (тестовые номера +7 999 000-00-01 / 02 / 03). Виден только в режиме разработки
  или при `EXPO_PUBLIC_DEV_LOGIN=1` в `.env`.
- Светлая и тёмная тема (переключатель на каждом экране входа и в кабинете).
- Согласие на обработку персональных данных при регистрации (152-ФЗ), время согласия сохраняется.

## Запуск

```bash
npm install
npx expo start          # QR-код → Expo Go
npx expo start --web    # в браузере
```

Ключи Supabase — в `.env` (образец `.env.example`).

## Сервер

- Проект Supabase — **pro-insult-app** (`exjpswhcriymikhsnvdz`). Старый проект prototipe не используется.
  Бесплатный проект засыпает после 7 дней без активности — включается в панели кнопкой Restore.
- Схема базы: `supabase/schema.sql` (выполняется целиком, повторно — тоже можно).
- Вход по телефону включён. Тестовые номера без СМС: +7 999 000-00-01 … 04, коды 111111 … 444444.
- Отправка настоящих СМС: функция `public.send_sms_hook` в базе (`supabase/sms-hook.sql`) отправляет код
  через SMS.ru. Ключ SMS.ru хранится в Vault базы под именем `smsru_api_id` (кладётся вручную, см. файл).
- **Не работает:** SMS.ru отклоняет отправку (ошибка 221) — нужен зарегистрированный буквенный отправитель,
  а физическим лицам SMS.ru его не регистрирует. Нужен другой способ доставки кода (решение отложено).
  Ответы SMS.ru видны в таблице `net._http_response`.

## Где хранятся данные

Сейчас — облачный Supabase (бесплатный тариф, сервер за рубежом): только разработка и тестовые данные.
Для реальных пациентов (152-ФЗ) — переезд на свой сервер в России: `infra/server/setup.sh` ставит
Supabase на чистую Ubuntu 24.04 одной командой (Docker, HTTPS через Caddy, вход по телефону, СМС-хук,
ежедневные резервные копии). Код приложения при переезде не меняется — только адрес и ключ в `.env`.

```
infra/server/     установка собственного сервера (на будущее)
```
